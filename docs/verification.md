## 预览反复选择语言包（构建 51–52）

- 用户确认出现的是 Poieva 自己的「语言包」窗口，不是系统下载确认框或语言识别对话框。只读查询表明简体中文 ↔ 英文均为 `installed / isReady=true`，繁体中文 ↔ 英文为 `supported / isReady=false`；此环境已有简体能力，缺少独立繁体模型。
- 使用公开固定句「這個工具可以保留原來的格式。」复现更改前的判断逻辑，得到「首次使用繁体中文 → 英文需要先准备系统语言包」；英文对照正常。此结果证明一个可重复的触发条件，不把它当作用户每次弹窗的唯一原因。
- 系统翻译新增已安装模型路由：优先使用原请求的精确语言组合；该组合未就绪时，简繁中文可借助本机文字转换复用另一套已安装中文模型。只转换送入模型的自然语言片段或返回文字，保留原请求、原文、选区、格式、代码和网址；仍尊重要求的译文书写形式，没有改用其他远程服务。
- 查询实际 `installedSource` 会话的 `isReady`，复用同一个已就绪会话进行翻译；这些会话不能请求下载。已安装但尚未就绪时提示稍后重试，确实缺少可用模型时才返回缺包错误，不把所有系统错误都引向语言包管理。

## 固定密钥组件与真实跨更新验证（构建 47–49）

- 构建 43 的真实记录在用户允许后同会话连接成功，重启仍失败。系统日志明确是 `ACL partition mismatch`：旧记录仅包含旧 `cdhash`，当前进程签名本身有效。这证明固定证书与默认登录钥匙串的分区校验是两个层面，不能把之前独立临时钥匙串的成功外推到登录钥匙串。
