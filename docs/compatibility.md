# 跨应用兼容性

更新日期：2026-10-28。当前版本包含紧凑界面、可选动效提示、自定义翻译服务管理与工作台服务多选。新增服务适配不改变目标应用的辅助功能接口能力。

Poieva Translate按输入控件暴露的能力处理文本，不按 QQ、Notion 等应用名称分支。通用机制已实现并通过自动检查；这不等于每个应用已经实测可用。

## 处理方式

1. 在用户触发快捷键时，识别前台应用的当前焦点，沿明确的焦点关系和有限层级的父节点寻找编辑控件。不会遍历整页正文来寻找输入框。
2. 目标应用没有提供可用控件时，尝试请求其启用 `AXManualAccessibility`，必要时请求 `AXEnhancedUserInterface`，并等待控件初始化。只在目标应用中请求，按进程缓存；不修改 macOS 隐私授权。
3. 输入框翻译只接受能确认范围的文字控件。网页根节点、聚合多个编辑块的容器和密码框不作为整框回填目标。
4. 优先设置控件自身的局部文字选区，或复用已经确认的完整选区。键盘全选只用于符合条件的控件，不通过重复全选扩大范围。网页控件无法证明局部范围时，提示用户选中文字后使用选中翻译。
5. 输入框翻译有选区时只替换选区，无选区时翻译整框。回填前核对应用、焦点、实际选中文字和已知选区。分块编辑器的全文值和文档选区可能采用不同位置基准，不能仅凭二者对不上就误报原文变化；可对应的全文值用于额外检查。粘贴后检查结果，无法确认时保留译文并提示核对，不把发出粘贴等同于完成回填。
6. 临时使用剪贴板后，仅在剪贴板仍属于本次操作时恢复；用户新复制的内容不会被延迟恢复覆盖。

Electron 官方说明了第三方工具通过 macOS 辅助功能接口请求应用启用可访问性的方式：[Accessibility](https://www.electronjs.org/docs/latest/tutorial/accessibility)。本项目独立实现文本获取和回填，没有引入其他翻译工具的代码。

## 格式保留

- 纯文本按段落、行和样式标记拆分，只翻译正文；保留原换行类型、空行、缩进、Markdown 标题、列表、表格分隔线、强调标记和链接地址。
- HTML 按文字节点翻译，保留标签、属性及块结构。解析只处理字符串，不使用浏览器渲染，不执行脚本或加载外部资源。
- RTF 按原属性范围重建文字，保留字号、字体、强调和段落样式。字体本身不决定是否翻译，避免将等宽字体的普通文字误判为代码；代码保护仍依据明确的代码标记。
- 自动回填和结果窗口的复制均携带已取得的格式。两个快捷键的用途仍有区别：「输入框翻译」替换选区或整框，「选中文字翻译」仅在窗口预览。
- 无法对齐格式数据、含不支持的图片或嵌入对象、或多行网页内容没有可用格式数据时，不自动降级为纯文本覆盖；保留译文并提示。

目前仅验证了通用 HTML、RTF 样例和纯文本结构，未承诺保留 Notion 专有数据库、嵌入块或所有自定义组件。富文本按原样式片段翻译，片段之间的上下文可能影响翻译自然度；目标应用也可能重新解释剪贴板格式，仍需要在具体应用中验收。

## 控件类型

| 控件 | 输入框翻译 | 选中文字翻译 |
| --- | --- | --- |
| 原生文字输入框 | 读取控件内容，核对后替换 | 读取选区，必要时复制 |
| 提供局部范围的网页输入框 | 优先设置局部范围，再验证 | 读取选区，必要时复制 |
| 分块编辑器 | 无选区时仅处理能确认的单个控件；有选区时核对选中文字并保留可用格式 | 只读取用户选中文字，携带可用格式复制 |
| 页面根节点、多个编辑块的容器 | 拒绝整框替换；明确可编辑且有已验证选区时可替换该选区 | 有可读取或可复制的选区时可尝试 |
| 密码输入框 | 拒绝 | 拒绝 |
| 未提供辅助功能文字接口的应用 | 提示更换具体输入位置或使用工作台 | 可尝试复制选区；仍失败时使用工作台 |
