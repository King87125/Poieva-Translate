# 模型管理与配置文件

苹果系统翻译是初始默认服务，始终保留在列表中。服务选择在本机保存，重启后沿用；删除正在使用的自定义服务时恢复为苹果翻译。

## 使用

模型管理统一保存翻译接口和 AI 模型配置。每项标明可用的用途：苹果、专业翻译和自定义 HTTP 为「翻译」；符合远程 API 条件的 OpenAI 兼容模型为「翻译、辅助」。用途标签表示支持的能力；默认翻译与辅助 API 的实际选择仍分开。

1. 打开「设置 → 模型管理 → 管理…」，点击「添加…」。
2. 先选择服务类型，再填写该类型的字段。专业翻译服务预填官方地址，不需要填写 AI 模型名称。OpenAI 兼容类型接受基础地址或完整的 `/chat/completions` 地址；远程服务使用 HTTPS，本机 localhost/回环地址可使用 HTTP。
3. 根据服务要求填写自己的账户信息和密钥。本机免鉴权模型可留空密钥；专业服务调用前必须填写密钥。编辑已有服务时，密钥留空表示保留，勾选「清除已保存的密钥」才会删除。更换服务类型、应用 ID、地址的域名、协议、端口或 HTTP 鉴权方式后，需要重新填写密钥或明确清除。
4. 可点击「测试连接」，用固定的 `Hello.` 英译中样例检查接口和返回格式。只有手动点击才会测试，可能产生服务商用量；此操作不保存配置、不切换服务。
5. 保存后选中服务并点击「设为默认」，也可从设置里的「默认服务」切换。工作台已有原文时会用新服务重新翻译；切换时旧请求取消，迟到结果不再更新界面。

自定义服务会收到待译正文，使用方自行承担相应账号、网络和服务费用。保留代码选项开启时，受保护的代码和网址由本机保留，格式结构也在本机重组。模型返回缺段、重复段、额外换行、截断或无法解析时拒绝回填，保留原文。

## 工作台服务选择

工作台保持顶部语言设置、下方原文/译文双栏。右上角「翻译服务」使用 macOS 原生菜单，直接勾选或取消服务，即时生效；没有独立的对比模式、确认窗口或勾选数量上限。选择一个时显示一份译文，选择多个时分别显示。全部取消则清空译文并暂停工作台请求，重新勾选后继续。导入配置不会自动勾选或发送请求。

- 只选择一个时更新默认服务；选择多个时工作台分别请求所选服务，全局快捷键继续使用默认服务。多选状态不持久化，也不随配置导出。
- 右栏按服务列表顺序显示各份译文；每份结果可独立复制，失败显示在对应服务下，可单独重试。
- 输入提交并停顿约 0.55 秒后，各服务自动翻译。组字、清空、修改语言和取消均作用于所有当前请求；旧输入、旧配置或已移除服务的迟到回复不会覆盖新结果。取消时保留已经完成的结果。
- 编辑所选服务会使用新配置重新翻译；删除服务后移出选择，剩一个时显示单份译文。每个勾选的自定义服务都会收到待译正文并计入对应服务商用量。

添加/编辑服务窗口以浅灰底区分服务信息、连接字段和高级参数，白色输入框使用更清楚的边界；标签放在输入框上方。「高级参数」整行均可点击展开。服务类型、语言和选项使用统一灰底按钮与原生菜单。

## 当前适配范围

| 服务类型 | 用户填写 | 可选配置 | 配置标识 |
| --- | --- | --- | --- |
| DeepL | API Key、账户对应的 API 地址 | 语气、翻译模型 | `deepl` |
| 百度通用翻译 | APP ID、密钥 | 已开通的术语干预 | `baidu-translate` |
| 有道文本翻译 | 应用 ID、应用密钥 | 已开通的翻译领域、术语表 ID | `youdao-v3` |
| OpenAI 兼容 | 地址、模型名称、所需密钥 | JSON 输出模式、模型请求参数 | `openai-chat-completions` |
| 自定义 HTTP 翻译 | 完整接口地址、接口模板、所需密钥 | 模板定义的引擎/其他选项 | `custom-http` |

DeepL 使用 `DeepL-Auth-Key` 鉴权，默认地址为 `https://api.deepl.com/v2/translate`；API Free 账户可选 `https://api-free.deepl.com/v2/translate`。按返回顺序核对整批译文，不让服务改写结构标记。语气和模型选项是否可用取决于语言与服务账户。[官方接口文档](https://developers.deepl.com/api-reference/translate)

百度使用通用文本翻译接口的 APP ID + 原文 + 随机数 + 密钥签名，POST 表单发送。多段合并时以换行分隔，按标准版单次 1,000 字符和接口字节上限分批（以 UTF-16 长度保守计数，包含批次分隔符），核对返回的原文和段数；请求间隔至少约 1 秒，兼顾低频账户。这里的 APP ID 不是百度智能云 OAuth API Key。[官方接口文档](https://fanyi-api.baidu.com/doc_bd/21)、[版本限制说明](https://fanyi-api.baidu.com/doc/13)

有道使用文本翻译 v3 签名，按接口长度限制拆分，使用严格语言方向，不请求语音结果。计算机、医学、金融、游戏等领域及术语表需用户在对应服务账户开通；普通使用保持「通用」。[官方接口文档](https://ai.youdao.com/DOCSIRMA/html/trans/api/wbfy/index.html)

长段落会优先在标点或空白处拆分，保留原有换行、缩进和格式结构。服务分段本身仍可能影响上下文与译文自然度。任何一批失败时不提交部分回填，也不自动重试或改用另一家服务。

OpenAI Chat Completions 兼容类型使用用户填写的模型和地址，普通 Bearer 鉴权，非流式批量翻译。模型需要遵守内置翻译指令并返回带原段落 ID 的 JSON；不会把返回的 Markdown 代码围栏或解释文字当作译文。

「高级参数」可以填写模型支持的 JSON 请求参数，例如 `{"temperature":0}`，也可启用该接口支持的 JSON 输出模式。不同模型的参数和能力不同，应以服务商文档为准。参数不能替换模型、消息、输出协议、工具或鉴权字段，不支持通过配置执行代码或加载脚本。

目前未提供 Responses、Anthropic Messages、模型列表拉取或自定义提示词。新增协议时可扩展适配类型和 `TranslationServiceFactory`，继续复用同一套服务管理、格式处理和回填保护。本次未新增腾讯旧 TMT 文本接口：官方更新历史已移除 `TextTranslate`，其文本服务亦有调整安排，后续应根据新接口文档适配。[官方更新历史](https://cloud.tencent.cn/document/api/551/17231)、[服务调整公告](https://cloud.tencent.cn/announce/detail/2448)

## 自定义 HTTP 接口

此类型使用固定地址的 POST JSON 请求及 JSON 响应。导入模板后，用户只需填写自己的密钥，并选择模板提供的选项。要创建其他接口，可在添加服务时选择「自定义 HTTP 翻译」，填写地址，并在「高级参数 → 接口模板 JSON」调整定义。模板编辑错误会阻止保存/测试，不会悄悄沿用旧定义发送请求。

[`Examples/lingdong-http.json`](../Examples/lingdong-http.json) 是按[灵动翻译文档](https://gg.ldfy.cc/APIDocument)编写的可导入包。默认 Google，可在编辑窗口切换 DeepL、百度和有道。请求发送到 `https://ldfy.cc/translation/language/translate`，使用 `text`、`sourceLang`、`targetLang` 和引擎编号 `type`；提取 `data.translatedText`，检查业务状态 `code = 200`。401、402、429 使用模板预置的密钥、余额和限频提示。没有调用真实服务商账户验证；本机集成检查对四个引擎分别校验字段和语言代码。

`http` 字段定义接口，服务级 `parameters` 仅保存模板选项的当前值。以下是一个独立于服务商的基础定义：

```json
{
  "version": 1,
  "method": "POST",
  "authentication": "bearer",
  "request": {
    "text": "{{text}}",
    "source": "{{source}}",
    "target": "{{target}}"
  },
  "responsePath": "data.translatedText",
  "successPath": "code",
  "successValue": 200,
  "languageCodes": { "en": "en", "zh-Hans": "zh" },
  "maxCharacters": 2000
}
```

- `authentication` 可为 `bearer`（Authorization: Bearer）、`header`（通过 `keyHeader` 和非秘密的 `keyPrefix` 设置密钥请求头）或 `none`。密钥只从钥匙串/编辑中的密钥栏读取，不使用占位符在正文中传递。更改鉴权渠道后需重新提供或明确清除已保存密钥。
- `request` 是 JSON 对象，占位符为 `{{text}}`、`{{source}}`、`{{target}}` 和已声明的 `{{option.名称}}`。正文与选项按字符串填入，保留 JSON 转义；正文中长得像占位符的文字不会被再次展开。字段名与服务地址不能使用占位符。静态 JSON 数字、布尔值、数组和对象可保留。
- `responsePath` 使用点分隔的字段路径，数组索引用数字，例如 `data.0.text`。不支持 JSONPath 表达式、脚本或动态代码。结果须为非空单段字符串；换行结构由本机保留。
- `successPath` 可留空。填写后会与 `successValue` 进行类型严格的比较，缺失或不相等时拒绝返回译文。`errorMessages` 把错误码映射为模板里的提示，不显示服务端原始错误正文；未知业务错误使用固定提示。
- `languageCodes` 以应用的语言标识为键，例如 `zh-Hans`、`zh-Hant`、`en`、`pt-BR`；缺失的语言会在读取密钥/请求前报错。`sourceLanguageCodes` 可覆盖仅用于源语言的代码。
- `options` 定义下拉框：每项包含 `id`、`title`、`defaultValue` 和 `choices`；候选项包含 `value`、`title`，可带完整的 `languageCodes` 替换或 `sourceLanguageCodes` 覆盖。最多 8 个选项，每项最多 50 个候选值；当前值写入服务级 `parameters`。灵动模板用 `engine` 选项处理四套语言代码，无需写品牌专用代码。
- `maxCharacters` 是客户端每段请求的 UTF-16 长度上限（1–20,000），模板默认 2,000，并非服务方承诺的接口限制。过长内容按原边界拆分，逐段请求；换行、缩进、代码和网址继续由本机保护。任一请求失败不提交部分覆盖；取消后停止后续请求，无自动付费重试。
- 模板最多 32 KB，正文嵌套不超过 8 层，字段路径不超过 16 层。仅支持本页描述的 JSON HTTP 类型；OAuth 刷新、签名算法、GET、表单、XML、流式响应和服务方批量接口暂未加入此通用类型。现有官方百度/有道签名适配保留。

## 导入与导出

管理窗口可导出选中服务或全部自定义服务，使用系统文件面板保存 JSON 文件。苹果内置服务不需要导出。当前导出版本为 v3，新增 `http` 模板字段，仍能导入原有 v1/v2 配置。自定义 HTTP 需要 v3；旧版程序不支持该类型。完整示例见 [`Examples/professional-services.json`](../Examples/professional-services.json)，旧版示例见 [`Examples/translation-services.json`](../Examples/translation-services.json)：

```json
{
  "format": "typebridge.translation-services",
  "version": 3,
  "services": [
    {
      "name": "DeepL",
      "adapter": "deepl",
      "baseURL": "https://api.deepl.com/v2/translate",
      "model": "",
      "appID": "",
      "jsonMode": false,
      "parameters": {}
    }
  ]
}
```

- 文件包含服务名称、类型、地址、模型、非秘密的应用 ID、高级参数和 HTTP 模板；不包含密钥、本机配置 ID 或当前选择。密钥单独保存于 macOS 钥匙串，不写入配置文件或普通偏好设置。专业类型的 `model` 为空、`jsonMode` 为 `false`；百度和有道需要有效的 `appID`，导入示例后应改为自己的应用 ID。
- 导入先校验整个文件，再一次性添加；任一条无效则不更改服务列表。未知版本、未知适配类型和未知字段会被拒绝。每个导入服务获得新的本机 ID，不关联已有钥匙串密钥。
- 完全相同的配置跳过重复导入。同名但地址、模型等配置不同的服务作为独立条目添加，不覆盖已有服务。导入后当前服务保持不变，也不发起测试或翻译；使用前检查地址并填写自己的密钥。
- 文件最多 256 KB、50 个服务；本机列表最多 50 个自定义服务。高级参数最多 16 KB、嵌套不超过 8 层，不能包含鉴权字段。URL 不接受内嵌账号、密码、查询参数或片段。
- 自定义服务连接使用临时网络会话，无本机缓存或 Cookie，不跟随重定向，不在错误提示中展示服务端原始错误正文。服务商自身的数据处理以该服务的条款为准。

## 开发验证

`./scripts/test.sh` 使用隔离偏好设置、模拟凭据和模拟响应，覆盖配置校验、旧版兼容、导入原子性、重复处理、密钥不随配置导出、签名、分批、删除回退、接口返回校验及取消。多服务检查另覆盖独立完成与重试、单路失败、输入法组字、清空、取消、服务移除/重配、迟到回复、51 个服务不截断、超过四路的实际请求与全部取消选择。

另有可选的本机 HTTP 集成检查。在一个终端运行固定样例服务：

```sh
python3 scripts/mock-translation-service.py
```

在另一个终端运行：

```sh
TYPEBRIDGE_TEST_SERVER_URL=http://127.0.0.1:19081/v1 ./scripts/test.sh --filter LocalServiceIntegrationTests
```

此检查拒绝非回环地址，不使用真实密钥或付费服务。包括模型兼容接口、三种专业协议和自定义 HTTP 模板的真实 HTTP 请求；Python 端独立验证签名，使用固定测试凭据。样例服务仅用于开发验收，按固定字典返回「你好」→ `Hello` 等结果，未知文字原样返回，不是可用的翻译引擎；完成后用 Control+C 退出。

## 上下文与辅助模型

`TranslationRequest.guidance` 携带只读前后文和按目标语言/原文相关性筛选的个人偏好。前文截取末尾 600 字，后文截取开头 600 字。仅使用当前控件能够确认的范围，不为上下文发送 Select All，不遍历其他应用或页面。辅助功能不可读时，可以在工作台显式填写参考文字。

- `CompatibleTranslationProvider` 在原有用户消息的 `reference` 字段中携带前后文、风格、偏好及相关术语，仍一次调用。术语中的明确选择优先，文章已有风格优先于一般风格偏好；参考文字始终作为数据处理。
- `AssistedTranslationProvider` 复用原有文档拆分和渲染。普通服务先初译，再由一个独立 `TranslationAssistant` 调整所有待译片段；每个服务最多一次辅助调用，无自动重试或多轮审校。AI 初译已使用参考信息时不再调用辅助模型。无参考/相关偏好、相同语言、繁简转换、纯代码等路径不调用辅助模型。
- 辅助模型仅使用单独配置的远程 HTTPS OpenAI 兼容 API，默认关闭；UI 与运行时均拒绝本机回环端点和非模型服务。每个翻译实例独享辅助实例和取消状态，沿用原服务的钥匙串凭据，无跨服务共享会话。兼容服务不跟随重定向、不携带 Cookie，设置 `store: false`；服务方是否留存内容由其条款决定。开发测试可直接注入回环测试接口，不通过产品中的辅助服务选择。
- 兼容接口使用现有 JSON 模式配置。严格核验片段 ID、数量、重复项、空文本、换行、数字及受保护字符串；检查无法保证识别全部语义错误。只有所有片段通过才渲染和回填，取消/输入变化后拒绝迟到结果。
- 为限制辅助开销，辅助输入最多 128 个片段、原文合计 6,000 UTF-16 单位、初译合计 12,000 单位；接口默认最多输出 4,096 token。超长或无效结果明确报错，不静默标为已应用偏好。原有基础翻译的 20,000 字上限保留。
- `TranslationPreferenceStore` 使用独立的版本化本机记录，最多 500 字表达偏好、64 条术语。术语可指定目标语言，同语言同原文不可重复；指定语言的术语覆盖同名通用术语。相关性按原文包含术语检索，尚无向量库或自动学习。偏好不写入服务导出文件；上下文不持久化。

辅助层不再包含 `FoundationModels` 设备端推理代码或本机模型预设。旧记录中的 `system` 选择迁移为 `off`，其余个人偏好保留；应用启动时也会关闭已有本机 API 辅助选择，不自动激活任何远程 API。用户已有的普通服务配置不会因升级而删除，但本机服务不出现在辅助 API 候选中。基础苹果翻译仍使用原有 Translation 框架，保留既有默认行为。

本机 HTTP 集成样例只检验协议、参考信息、术语与结构流转，返回固定内容，不模拟真实模型能力。远程模型应按实际翻译样例、响应耗时与费用选择，当前没有真实远程小模型的质量或性能测试结论。
